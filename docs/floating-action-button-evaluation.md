# 悬浮按钮设计方案评估

## 问题描述

当前悬浮按钮使用 `+` 图标，含义模糊，用户难以理解按钮的作用。需要优化方案，降低用户理解成本。

## 方案评估

### 方案 A: 扩展悬浮按钮 (ExtendedFloatingActionButton)

**描述：** 主按钮收起时显示文字+图标，点击后展开显示选项

**收起状态：**
```
[添加计划 ✏️]  ← ExtendedFloatingActionButton
```

**展开状态：**
```
  手动添加        [+]
  自定义添加计划
  AI推荐        [✨]
  智能生成一周计划
      [收起 ✕]
```

| 优点 | 缺点 |
|------|------|
| 含义明确，符合 Material Design 规范 | 占用空间稍大 |
| 主操作清晰可见 | 需要自定义组件 |
| Google 官方推荐模式 | |

---

### 方案 B: 分离式按钮

**描述：** 直接显示两个独立按钮，无需展开

```
     [手动添加 +]  [AI推荐 ✨]
```

| 优点 | 缺点 |
|------|------|
| 两个操作都直观可见 | 可能显得拥挤 |
| 无需点击展开 | 不符合 Material FAB 规范 |
| 操作效率高 | 占用底部空间 |

---

### 方案 C: 标签式悬浮按钮

**描述：** 主按钮始终显示"添加"文字，点击展开选项

**收起状态：**
```
[添加 +]
```

**展开状态：**
```
  手动添加计划    [+]
  AI智能推荐      [✨]
      [收起 ✕]
```

| 优点 | 缺点 |
|------|------|
| 简洁清晰 | 文字较短，含义可能不够明确 |
| 点击即展开选项 | 需要额外点击 |

---

### 方案 D: 回到底部操作栏

**描述：** 放弃悬浮按钮，使用固定底部栏显示操作按钮

```
┌─────────────────────────────────┐
│                                 │
│         内容区域                │
│                                 │
├─────────────────────────────────┤
│   [手动添加]    [AI推荐]        │
└─────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 操作直观，易发现 | 占用屏幕空间 |
| 符合传统交互习惯 | 内容区域减少 |
| 无需学习成本 | 不够现代 |

---

### 方案 E: Speed Dial (速度拨号)

**描述：** 类似 Telegram 的速度拨号，主按钮周围环绕选项

```
         [AI推荐 ✨]
             ↑
[手动添加 +] ← [添加] → [快速记录 📝]
             ↓
         [更多 ...]
```

| 优点 | 缺点 |
|------|------|
| 动画效果炫酷 | 实现复杂 |
| 操作可见 | 可能过于花哨 |
| 符合现代 App 设计 | 选项多时会乱 |

## 竞品参考

建议调研以下 App 的悬浮按钮设计：

1. **Google Keep** - 扩展悬浮按钮，显示"添加笔记"
2. **Telegram** - Speed Dial 设计
3. **微信** - 底部操作栏
4. **Notion** - 悬浮按钮 + 展开菜单
5. **滴答清单** - 悬浮按钮 + 标签提示
6. **小红书** - 底部发布按钮

## Material Design 官方建议

参考：https://m3.material.io/components/floating-action-button/overview

- **Extended FAB**: 适合主要操作需要文字说明的场景
- **FAB**: 适合图标含义明确的场景
- **位置**: 右下角，距离边缘 16dp

## 决策要点

1. **用户心智**: "+" 号是否需要替代？
2. **空间占用**: 悬浮按钮 vs 底部栏
3. **操作频率**: 高频操作是否需要更直接？
4. **一致性**: 与 App 其他页面风格是否统一？
